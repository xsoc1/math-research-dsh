# 使用 2.0 与迁移现有项目

2.0 的基本工作单位仍是实际数学问题和项目已有材料. 选择当前有帮助的工具, 将有价值的理解留给下一次研究, 无须先建立完整流水线.

## 安装来源与旧副本

使用 marketplace `math-research` 的四个 `2.0.0` 组件, 安装后新开任务. 用 `codex plugin list --json` 核对实际 `pluginId`, `marketplaceName`, `version` 与 `enabled`; 磁盘里存在新版目录不代表当前任务已经加载它.

独立安装在 `skills/` 的旧技能, 或其他 marketplace 的同名插件, 具有各自的来源. 更新 `math-research` 不会自动卸载这些副本. 如果选择器出现同名入口, 选择来源为 `math-research`, 版本为 `2.0.0` 的组件. 保留有本地定制的副本及其原始内容, 不用重写个人插件来掩盖来源差异.

## 从哪里开始

| 当前工作 | 入口 |
| --- | --- |
| 读论文, 保存原文和定位, 建工具卡, 加批注 | [文献与经验工具](../skills/manage-math-research-program/references/v2-library.md) |
| 从成功或失败证明中提取理解 | [研究经验](../skills/rigorous-open-math-research/references/v2-research-experience.md) |
| 保存当前状态, 续接编译或其他任务 | [续接工具](../skills/math-research-workflow/references/v2-continuity.md) |
| Lean 编译反馈与精确目标检查 | [Lean 工具](../skills/lean-verify/references/v2-verification.md) |
| 项目已有 Blueprint, 需要操作已接受知识 | [运行时入口](../skills/manage-math-research-program/references/blueprint-runtime-gateway.md) |

例如, 研究者发现某条路线因一个粗糙放缩丢失相位信息而停住. 可以只留一张经验卡, 指出放缩步骤, 适用范围和证据位置. 后续读到更强的相位估计时, 检索这张卡并重新尝试. 方法在局部失败不等于定理被否证, 中断或没有返回也不等于数学失败.

## 保留什么, 重建什么

保留论文原文, 版本, 证明与审计包, 批注, 检查点和计算证书的原字节. 工具索引, 检索视图, 路线比较视图和编译缓存可以重建. 生成视图要保留人写的解释与疑问, 不能把猜想或直觉自动升级成定理.

旧工具卡允许渐进维护. 某一张卡存在坏元数据时, 报告该卡的问题并继续提供其他可用材料. 改版后保留旧批注与旧版本的联系, 不把旧批注无声地改成对新版本的背书. 来源定位应指向实际读取内容, 抽取文字存在公式损坏时回到 PDF 或原始文件核对.

## 续接的改变

现有 `RESUME.md` 或研究白板继续使用. 当前内容优先于历史快照; 下一步是建议, 可以根据新的数学理解调整. 数据写入时的哈希检查用于避免覆盖较新内容, 不作为研究方法的审批门槛.

持久任务按原 ID 查询, 并核对输入与实际进程身份. 同一动作的结果不明时先对账, 其他研究工作可继续. 本地任务记录与外部任务收据只说明执行情况, 不自动作出数学裁决. 外部服务接口没有实际接入时, 仅记录通用协议及其模拟范围.

旧版的 sealed checkpoint / receipt 可以继续使用 [兼容工具](../skills/math-research-workflow/references/v1-compatibility.md). `validate_pipeline.py` 默认只检查当前续接数据; 旧完整协议需明确加 `--legacy-v1`. 历史 benchmark 的时限与封存规则只约束对应实验.

## Lean 结果的改变

分开理解执行结果, 目标语义, 根依赖闭合和证据身份. 完成一个文件或条件引理的构建不等于完成原定理. 核对实际 elaborated 类型, 隐式前提, 关键定义和传递公理; 语义复核还需要判断这些是否表达了委托的数学问题.

旧验证结果按旧 schema 与实际记录读取. 缺少 2.0 字段不会触发全项目重审, 但需要依赖某个结果时应补查与本次用途有关的真实缺口. 新旧输入或依赖环境不一致时不能复用旧的通过状态. 证明体改变后应重新机器检查, 语义不变的部分可以保留已有语义复核.

## 验收怎样解释

[实施记录](https://github.com/xsoc1/rigorous-open-math-research/blob/72a1cc17ce98f3d3fd3b001d7b25d442ba2d3803/docs/v2.0-implementation-status.md) 给出实际执行范围. 保存了 PDF 不等于理解了论文, 下载和指针命中不等于后续复用正确. 相同地, 入口字节减少不等于数学能力提高. 应分别考察首次整理, 后续检索, 适用性判断, 跨问题复用, 人的理解与长期研究进展.
